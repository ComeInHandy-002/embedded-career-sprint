# 项目二：FreeRTOS + CAN 工业传感节点

目标硬件：NUCLEO-F446RE、BME280、SN65HVD230、CANable 兼容 USB-CAN、2 只 120 欧姆终端电阻。截止日期：2026 年 10 月 4 日。

当前能力按 CAN 零基础计算。前置条件是项目一通过全部测试，并完成 6 小时 CAN 入门。这个仓库提供需求、接口和测试约束；核心代码必须本人从空工程实现。

## 先过 CAN 入门关

进入驱动编码前，必须能脱离资料回答：

1. 标准帧的标识符、DLC、数据和 CRC 各自做什么。
2. 两个节点同时发送时为什么标识符数值更小的帧优先，且不破坏获胜帧。
3. 为什么总线两端各放 120 欧姆，断电测量 CAN_H 到 CAN_L 为什么约为 60 欧姆。
4. CAN_H/CAN_L 是差分信号，不能只看“CAN 比 LIN 快”来判断是否掌握协议。
5. 错误主动、错误被动和 bus-off 的行为差异，以及恢复前为什么要记录原因。

未通过这五项口述验收时，不开始 FreeRTOS + CAN 整合。

## 固定硬件与总线参数

- I2C1：BME280。
- USART2：板载虚拟串口，只用于 CLI 和调试日志。
- bxCAN：连接 SN65HVD230 的 TXD/RXD；具体引脚由 CubeMX 确认后记录。
- CAN 总线：`500 kbps`、11 位标准帧、两个物理端点各 120 欧姆。
- CANable：电脑端发送命令、抓取时间戳和保存测试日志。
- 独立看门狗：只有五个关键任务的健康条件全部满足时才喂狗。

## 任务结构

| 任务 | 周期/触发 | 职责 | 主要通信方式 |
|---|---|---|---|
| `SensorTask` | 100 ms | 读取或获取最新传感器数据，更新状态和错误计数 | 传感快照 + 互斥锁 |
| `CanRxTask` | 接收通知 | 校验 ID/DLC/命令/范围，执行阈值命令并生成回复 | 任务通知 + 接收队列 |
| `CanTxTask` | 100 ms / 1 s / 回复事件 | 组帧并发送 `0x180`、`0x181`、`0x281` | 发送队列 |
| `LogTask` | 日志队列事件 | 通过 UART 输出非关键日志，拥堵时允许丢弃低优先级日志 | 日志队列 + UART 互斥锁 |
| `HealthTask` | 500 ms | 检查任务心跳、CAN 超时、错误状态和看门狗条件 | 事件组 + 错误统计 |

CAN 接收中断只复制原始帧到预分配队列并通知 `CanRxTask`；不得在中断里解析业务、打印日志、等待互斥锁或阻塞。多个任务不得直接修改同一份传感器结构。

## 字节序和公共约定

- 多字节整数统一使用小端序，仓库 README 必须给出一个字节拆分示例。
- 温度使用有符号整数，单位为 `0.1 摄氏度`；湿度使用无符号整数，单位为 `0.1%RH`。
- 发送计数或错误计数溢出时采用饱和或自然回绕，必须在设计说明中选择一种并测试。
- 未使用字节固定填 `0x00`，接收端对要求固定长度的帧严格校验 DLC。

## CAN 报文接口

| CAN ID | 周期/方向 | DLC | 数据定义 |
|---|---|---:|---|
| `0x180` | 节点发送，100 ms | 8 | B0-B1 温度×10 `int16_le`；B2-B3 湿度×10 `uint16_le`；B4 状态位；B5 序号；B6-B7 保留 0 |
| `0x181` | 节点发送，1 s | 8 | B0-B3 运行时间秒 `uint32_le`；B4 传感器错误数；B5 bus-off 次数；B6 复位原因；B7 健康状态 |
| `0x280` | PC 发送，按需 | 依命令 | B0 命令号；其余字节见命令表 |
| `0x281` | 节点回复，按需 | 8 | B0 命令号；B1 执行结果；B2-B3 最终生效值；B4-B7 保留 0 |

### `0x280` 命令表

| 命令 | DLC | 请求数据 | 合法范围 |
|---|---:|---|---|
| `0x01` 设置温度阈值 | 3 | B1-B2 为 `int16_le` 温度×10 | -400 至 850 |
| `0x02` 设置湿度阈值 | 3 | B1-B2 为 `uint16_le` 湿度×10 | 0 至 1000 |
| `0x03` 清除可清错误 | 1 | 无参数 | 只清软件统计，不清复位原因 |

执行结果：`0x00` 成功，`0x01` 未知命令，`0x02` DLC 错误，`0x03` 参数越界，`0x04` 当前状态不允许。非法请求不得改变旧值，也必须留下计数和可验证回复。

## 状态与恢复

- `0x180` B4 至少包含：传感器在线、温度报警、湿度报警、CAN 接收超时、队列拥堵。
- 收到第一条合法 `0x280` 后，若连续 5 秒没有再收到合法命令，`HealthTask` 置 CAN 接收超时位；下一条合法命令到达后清除。它是诊断告警，不阻止周期发送。
- 检测到 bus-off 时停止普通发送请求、递增计数、记录时间和错误码，按 HAL/bxCAN 状态确认恢复；恢复后先发送一帧健康状态再回到正常周期。
- 传感器断线时保留最后有效值或发送约定无效值，二者必须择一并写入 README；状态位必须明确标记离线。
- 看门狗复位后在 `0x181` 中上报复位原因，不能只重新启动而不留证据。

## 明确不做

- 不实现完整 UDS、ISO-TP、DBC 自动代码生成、Bootloader 或 OTA。
- 不把 CANoe 接触经历写成熟练掌握；本项目优先用 CANable 完成可复现实验。
- 不追求复杂 UI；电脑端只需能发帧、看时间戳并保存日志。
