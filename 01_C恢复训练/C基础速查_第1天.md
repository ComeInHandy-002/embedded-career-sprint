# C 基础速查：第 1 天

这份速查用于完成第一次独立尝试之后复盘，不是开始编码前照抄的答案。它不包含四个诊断函数的完整实现。

## 1. 函数接口先看契约

看到一个函数声明时，先写清四件事：

1. 哪些参数是输入。
2. 哪些指针用于返回结果。
3. 什么情况算参数非法。
4. 失败时允许改变哪些数据。

例如“通过输出指针返回结果”的函数，只有成功时才能写入输出位置。否则调用者无法区分旧值和失败过程中写入的垃圾值。

## 2. 数组参数不携带长度

数组传入函数后，本质上只给了首元素地址。函数不能通过这个地址知道数组有几个元素，因此必须另外传入长度。

- 指针不为空，不代表数组一定有元素。
- 长度为 0 时，求和可以定义为 0，但“最大值”没有合理结果。本练习的测试契约要求最大值函数失败。
- 访问下标前，必须确保下标严格小于长度。

## 3. 输出指针的处理顺序

推荐思考顺序：

1. 先检查所有必须有效的指针和长度。
2. 在局部变量中完成计算。
3. 成功后再把结果写入输出指针。
4. 最后返回成功状态。

不要在空指针检查前使用 `*pointer`，也不要在确定成功前覆盖调用者的输出值。

## 4. 循环与 `size_t`

- 数组长度和下标使用 `size_t`。
- 常见遍历条件是“下标小于长度”，不是“小于等于长度”。
- 无符号数减到 0 以下会回绕成很大的数，因此倒序循环需要特别谨慎。
- 编译器没有警告不代表逻辑正确，但警告必须先清零再看测试失败。

## 5. 全负数数组的最大值

如果把候选最大值初始化为 0，那么全负数数组会得到错误结果。非空数组可以用第一个元素建立初始候选值，再从后续元素继续比较。

## 6. 原地反转的状态

原地反转只需要两个位置：一个从左侧开始，一个从右侧开始。交换后两者向中间靠拢，直到相遇或交错。

先在纸上画出长度分别为 0、1、2、5 时的位置变化。特别留意：长度为 0 时不能直接计算“长度减 1”再作为有效下标。

## 7. 编译与测试的分工

- 编译失败：先修第一条编译器信息，不要同时改很多处。
- 编译成功、测试失败：阅读第一个失败用例的输入和预期状态。
- 测试增加：确认是实现正确，而不是删掉检查或硬编码测试数据。
- 所有测试通过：再解释边界情况，并添加 Git 提交。
